# دليل مدير نظام مركز طيبة

## نظرة عامة

هذا الدليل يستهدف مديري النظام الذين يسيطرون على إعدادات النظام وإدارة المستخدمين.

## إدارة المستخدمين

### إنشاء مستخدم جديد

#### من واجهة النظام
1. سجّل الدخول كمدير
2. اذهب إلى **إدارة المستخدمين**
3. اضغط **إضافة مستخدم**
4. أدخل البيانات:
   - **الاسم**: اسم المستخدم
   - **البريد الإلكتروني**: البريد الإلكتروني (يتطلب Firebase Auth)
   - **كلمة المرور**: 6 أحرف على الأقل
   - **الوظيفة**: الوظيفة الحالية
   - **الراتب الشهري**: الراتب
   - **النوع**: دوام كامل / جزئي
   - **الصلاحيات**: اختر الصفحات المتاحة
5. اضغط **حفظ**

#### من سطر الأوامر
```bash
curl -X POST https://your-app.railway.app/api/admin/create-user \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <firebase-id-token>" \
  -d '{"email":"newuser@taiba.com","password":"securepassword123"}'

# الاستجابة:
{ "uid": "firebase-auth-uid-here" }
```

### تعديل بيانات مستخدم

1. اذهب إلى **إدارة المستخدمين**
2. اضغط **تعديل** بجانب المستخدم
3. عدّل البيانات المطلوبة:
   - **الاسم**: يمكن تغييره
   - **البريد الإلكتروني**: لا يمكن تغييره بعد الإنشاء
   - **الوظيفة**: يمكن تغييرها
   - **الراتب الشهري**: يمكن تغييره
   - **الصلاحيات**: يمكن تعديلها
4. اضغط **حفظ**

> **ملاحظة:** لا يمكن تغيير البريد الإلكتروني بعد الإنشاء. لإعادة تعيين كلمة المرور، استخدم "إعادة تعيين كلمة المرور".

### حذف مستخدم

#### من واجهة النظام
1. اذهب إلى **إدارة المستخدمين**
2. اضغط **حذف** بجانب المستخدم
3. اضغط **تأكيد**

#### ما يحدث عند الحذف:

```
1. يتم محاولة حذف المستخدم من Firebase Auth ( عبر API)
2. يتم حذف المستخدم من Firestore
```

> **تنبيه مهم:**
> - الحذف يزيل المستخدم من Firestore
> - حساب Firebase Auth يحاول حذفه عبر API
> - إذا فشل حذف Firebase Auth (مثلاً: لا يوجد Admin SDK)، سيبقى الحساب في Firebase Auth
> - لا يمكن التراجع عن الحذف

#### قبل الحذف، تأكد من:
- أخذ نسخة احتياطية
- عدم وجود مبيعات مرتبطة بالمستخدم
- إبلاغ المستخدم بالحذف

### إعادة تعيين كلمة المرور

#### من واجهة النظام (متاح)
1. اذهب إلى **الإعدادات**
2. في قسم **إعادة تعيين كلمة المرور**
3. أدخل البريد الإلكتروني للمستخدم
4. اضغط **إرسال رابط إعادة التعيين**
5. سيتلقى المستخدم رابطاً عبر البريد الإلكتروني
6. يتبع المستخدم الرابط لإعادة التعيين

#### من سطر الأوامر
```bash
curl -X POST https://your-app.railway.app/api/admin/reset-password \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <firebase-id-token>" \
  -d '{"email":"user@taiba.com"}'
```

> **ملاحظة:** هذه الطريقة ترسل رابطاً عبر البريد الإلكتروني. المستخدم يتبع الرابط لإعادة التعيين.

### تغيير كلمة المرور (للمستخدم نفسه)

#### من واجهة النظام (متاح)
1. سجّل الدخول
2. اذهب إلى **الإعدادات**
3. في قسم **تغيير كلمة المرور**:
   - أدخل كلمة المرور الجديدة
   - أكّد كلمة المرور الجديدة
4. اضغط **تغيير كلمة المرور**

> **ملاحظة:** يتطلب تسجيل دخول حديثاً (آخر ساعة). إذا فشل التغيير بخطأ `auth/requires-recent-login`:
> 1. سجّل خروج
> 2. أعد تسجيل الدخول
> 3. جرّب التغيير مرة أخرى

## إدارة الصلاحيات

### الصلاحيات المتاحة

| الصلاحية | الوصف |
|----------|-------|
| `dashboard` | لوحة التحكم |

| `inventory` | المخزون |

| `expenses` | المصاريف |
| `employees` | إدارة المستخدمين |

### تغيير صلاحيات مستخدم

1. اذهب إلى **إدارة المستخدمين**
2. اضغط **تعديل** بجانب المستخدم
3. عدّل الصلاحيات (حدد/ألغ التحديد)
4. اضغط **حفظ**

### صلاحيات مدير النظام

مدير النظام يجب أن يملك جميع الصلاحيات:
```
dashboard, pos, invoices, inventory, reports, expenses, employees, settings
```

## إدارة الدوام

### متابعة سجل العمل

1. اذهب إلى **إدارة المستخدمين**
2. اضغط تبويب **سجل العمل**
3. استخدم الفلاتر:
   - **الكل**: جميع السجلات
   - **اليوم**: سجلات اليوم فقط
   - **آخر 7 أيام**: سجلات الأسبوع الأخير
   - **آخر 30 يوم**: سجلات الشهر الأخير
   - **نطاق مخصص**: اختر تاريخ البداية والنهاية

### تصدير سجل العمل

1. اذهب إلى **إدارة المستخدمين**
2. اضغط تبويب **سجل العمل**
3. اضغط **تصدير Excel**
4. سيُحمّل ملف Excel يتضمن:
   - **سجل العمل**: تفاصيل كل دوام
   - **ملخص المبيعات**: إجمالي لكل موظف

### ملخص الدوام

| البطاقة | الوصف |
|---------|-------|
| إجمالي ساعات العمل | مجموع ساعات الدوام لجميع الموظفين |
| عدد الموظفين | عدد الموظفين الذين سجّلوا دوام في الفترة |
| عدد المبيعات | عدد المبيعات المسجلة |
| إجمالي المبيعات | المبلغ الإجمالي للمبيعات |

## النسخ الاحتياطي والاستعادة

### أخذ نسخة احتياطية

1. اذهب إلى **الإعدادات**
2. اضغط **تنزيل نسخة احتياطية**
3. سيُحمّل ملف JSON يتضمن:
   - المنتجات
   - المبيعات
   - المصاريف
   - الموظفين
   - العملاء
   - الموردين
   - سجل الدوام
   - الأقسام والمواسم

> **ملاحظة:** النسخة الاحتياطية لا تتضمن كلمات المرور (لأنها في Firebase Auth، وليس Firestore).

### استعادة البيانات

#### من واجهة النظام
1. اذهب إلى **الإعدادات**
2. في قسم **استعادة البيانات**
3. اضغط **اختيار ملف**
4. اختر ملف النسخة الاحتياطية (JSON)
5. اضغط **استعادة**

> **⚠️ تحذير خطير:**
> - **الاستعادة تحذف جميع البيانات الحالية أولاً!**
> - **لا يمكن التراجع عن الاستعادة بعد تنفيذها!**
> - **خذ نسخة احتياطية حديثة قبل الاستعادة!**
> - **تأكد من أن ملف النسخة الاحتياطية سليم وصحيح!**

#### ما يحدث أثناء الاستعادة:
1. حذف جميع البيانات الحالية من Firestore
2. كتابة البيانات من ملف النسخة الاحتياطية
3. إعادة تحميل الصفحة تلقائياً

### إعادة ضبط المصنع

#### من واجهة النظام
1. اذهب إلى **الإعدادات**
2. في قسم **منطقة الخطر**
3. اضغط **إعادة ضبط المصنع**
4. اضغط **تأكيد**

> **⚠️ تحذير خطير:**
> - **هذا يحذف جميع البيانات نهائياً!**
> - **لا يمكن التراجع بعد التنفيذ!**
> - **خذ نسخة احتياطية أولاً!**

## استكشاف الأخطاء

### المستخدم لا يستطيع تسجيل الدخول

```
المشكلة: "البريد الإلكتروني أو كلمة المرور غير صحيحة"

الحلول:
1. تأكد من صحة البريد الإلكتروني
2. أعد تعيين كلمة المرور
3. تأكد من تفعيل Firebase Authentication
4. تحقق من Firestore Rules
```

### النظام لا يعمل

```
المشكلة: الصفحة البيضاء أو رسالة خطأ

الحلول:
1. تحقق من Railway Logs
2. تأكد من صحة Environment Variables
3. أعد تشغيل التطبيق
4. تحقق من Firebase Console
```

### النسخ الاحتياطي لا يعمل

```
المشكلة: فشل أخذ النسخة الاحتياطية

الحلول:
1. تأكد من اتصال الإنترنت
2. تحقق من Firestore Connection
3. جرّب مرة أخرى بعد دقائق
```

## الإعدادات المتقدمة

### Environment Variables

| المتغير | الوصف | مطلوب | ظاهر في الواجهة |
|---------|-------|-------|-----------------|
| `PORT` | رقم البورت | نعم | لا |
| `NODE_ENV` | بيئة التشغيل | نعم | لا |
| `FIREBASE_APPLET_CONFIG` | Firebase Config للسيرفر (JSON) | نعم | لا |
| `BOOTSTRAP_PASSWORD` | كلمة مرور الإعداد الأولي (سيرفر فقط) | اختياري | نعم |
| `GEMINI_API_KEY` | مفتاح Gemini AI | اختياري | لا |
| `ALLOWED_ORIGINS` | المصادر المسموحة | اختياري | لا |
| `GOOGLE_CLIENT_ID` | Google OAuth Client ID | نعم | لا |
| `GOOGLE_CLIENT_SECRET` | Google OAuth Client Secret | نعم | لا |
| `GOOGLE_REFRESH_TOKEN` | Google OAuth Refresh Token | نعم | لا |

> **ملاحظة:** جميع الطلبات تستخدم Firebase Auth token. لم يعد هناك `PROXY_SECRET` أو `X-Proxy-Token`.

## الأمان

### أفضل الممارسات

1. **كلمات المرور**: استخدم كلمات مرور قوية (8 أحرف على الأقل، أرقام + حروف + رموز)
2. **الصلاحيات**: لا تمنح صلاحيات زائدة عن الحاجة
3. **النسخ الاحتياطي**: خذ نسخة احتياطية بانتظام
4. **المراقبة**: راقب الأخطاء والنشاط غير العادي
5. **التحديث**: حدّث النظام بانتظام

### ما لا يجب مشاركته

- `GOOGLE_CLIENT_SECRET`
- `GOOGLE_REFRESH_TOKEN`
- `FIREBASE_APPLET_CONFIG`
- كلمات المرور

### ما يمكن مشاركته

- البريد الإلكتروني للمستخدمين
- أسماء المستخدمين
- الإحصائيات العامة
