# دليل ترحيل المستخدمين إلى Firebase Authentication

## نظرة عامة

هذا الدليل يشرح خطوات ترحيل مستخدمي النظام الحاليين من نظام المصادقة القديم (كلمات مرور مخزنة في Firestore) إلى Firebase Authentication.

## الخلفية

قبل WP-3، كانت كلمات مرور المستخدمين مخزنة كنص عادي في Firestore. بعد WP-3، يتم استخدام Firebase Authentication لإدارة المستخدمين.

### الفرق الرئيسي

| الجانب | قبل (القديم) | بعد (الجديد) |
|--------|--------------|--------------|
| تخزين كلمة المرور | Firestore (نص عادي) | Firebase Auth (مشفر) |
| هوية المستخدم | UUID عشوائي | Firebase Auth UID |
| تسجيل الدخول | مقارنة يدوية | Firebase SDK |
| إعادة تعيين كلمة المرور | غير متوفرة | عبر البريد الإلكتروني |

## المراحل

### المرحلة 0: الإعداد الأولي (Bootstrap Admin)

> **هذه ليست ترحيل** - هذه خطوة إعداد أولى.

متى يحدث:
- إذا لم يكن هناك مستخدمين في النظام
- عند أول تسجيل دخول

كيف يعمل:
```
1. المستخدم يُدخل البريد وكلمة المرور الافتراضية
2. النظام يتحقق من عدم وجود مستخدمين
3. يتم إنشاء حساب Firebase Auth بالبريد وكلمة المرور
4. يتم حفظ بيانات المدير في Firestore
5. يمكن للمستخدم تسجيل الدخول
```

> **ملاحظة:** كلمة المرور تُتحقق منها على السيرفر عبر `BOOTSTRAP_PASSWORD` (لا تظهر للعميل).

### المرحلة 1: الترحيل اليدوي (للمستخدمين الحاليين)

#### الخطوة 1: أخذ نسخة احتياطية

```bash
# من واجهة النظام
1. سجّل الدخول كمدير
2. اذهب إلى الإعدادات
3. اضغط "تنزيل نسخة احتياطية"
4. احفظ الملف في مكان آمن
```

> **⚠️ تحذير:** خذ نسخة احتياطية كاملة قبل أي تغييرات.

#### الخطوة 2: تشغيل Migration

```bash
# استدعاء API Migration (يتطلب Firebase Auth token)
curl -X POST https://your-app.railway.app/api/admin/migrate-users \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <firebase-id-token>"
```

#### الخطوة 3: مراجعة التقرير

الاستجابة ستكون:
```json
{
  "success": true,
  "results": {
    "migrated": [
      { "oldId": "550e8400-...", "newUid": "abc123...", "email": "user@taiba.com" }
    ],
    "skipped": [
      { "id": "xyz789...", "reason": "No password field (already migrated)" }
    ],
    "errors": [
      { "id": "error-id", "error": "Error message" }
    ]
  }
}
```

**تفسير النتائج:**
- `migrated`: المستخدمين الذين تم ترحيلهم بنجاح
- `skipped`: المستخدمين الذين تم تخطيهم (مدرجين بالفعل أو بدون بريد)
- `errors`: المستخدمين الذين فشل ترحيلهم

#### الخطوة 4: التحقق من Firestore

```bash
# تحقق من Firestore Console
# 1. افتح Firebase Console > Firestore
# 2. تحقق من collection employees
# 3. تأكد من أن جميع المستخدمين لديهم IDs جديدة (Firebase UIDs)
# 4. تأكد من عدم وجود حقل password في أي مستخدم
```

#### الخطوة 5: اختبار تسجيل الدخول

```
# لكل مستخدم مرحّل:
1. افتح النظام
2. أدخل البريد الإلكتروني وكلمة المرور القديمة
3. تأكد من نجاح تسجيل الدخول
4. تأكد من ظهور البيانات الصحيحة
```

### المرحلة 2: حذف كلمات المرور القديمة

> **مهم جداً:** بعد الترحيل الناجح، يجب حذف كلمات المرور القديمة من Firestore.

#### لماذا هذا مهم؟

كلمات المرور القديمة مخزنة كنص عادي في Firestore. هذا:
- خطأ أمني
- مخالفة لأفضل الممارسات
- غير ضروري بعد الترحيل

#### كيف تُحذف؟

```bash
# استخدام Firestore REST API
# لكل مستخدم تم ترحيله:
# 1. افتح Firebase Console > Firestore
# 2. ابحث عن المستخدم في collection employees
# 3. احذف حقل "password" يدوياً
```

> **ملاحظة:** حقل `password` لا يوجد في واجهة النظام بعد WP-3. لكنه قد يكون موجوداً في Firestore إذا تم الترحيل يدوياً.

### المرحلة 3: التحقق النهائي

```bash
# تحقق من:
# 1. جميع المستخدمين لديهم Firebase Auth UIDs
# 2. لا يوجد حقل "password" في أي مستخدم
# 3. جميع المستخدمين يمكنهم تسجيل الدخول
# 4. لا يوجد أخطاء في Firebase Console
```

## التعامل مع الأخطاء

### الخطأ: "البريد الإلكتروني مستخدم بالفعل"

هذا يعني أن البريد الإلكتروني موجود بالفعل في Firebase Auth.

**الحل:**
```bash
# تحقق من Firebase Console > Authentication
# 1. ابحث عن البريد الإلكتروني
# 2. إذا وجدته:
#    - تحقق من تطابق كلمة المرور
#    - إذا كانت مختلفة، استخدم "Reset Password"
# 3. إذا لم تجده:
#    - أعد تشغيل Migration
```

### الخطأ: "فشل إنشاء حساب المستخدم"

قد يكون بسبب:
- Firebase Auth غير مفعل
- API Key غير صحيح
- Firebase Config غير مُعد بشكل صحيح

**الحل:**
```bash
# 1. تحقق من Firebase Console > Authentication
# 2. تأكد من تفعيل Email/Password
# 3. تحقق من FIREBASE_APP_CONFIG
```

### الخطأ: المستخدم لا يستطيع تسجيل الدخول بعد الترحيل

**الحل:**
```bash
# 1. تحقق من Firestore > employees
# 2. تأكد من أن document ID = Firebase Auth UID
# 3. إذا كان الـ ID مختلفاً:
#    - أعد تشغيل Migration
#    - أو أعد إنشاء المستخدم يدوياً
```

## التعامل مع Rollback

### التراجع قبل أي تغييرات

```bash
# استعادة النسخة الاحتياطية
# 1. سجّل الدخول كمدير
# 2. اذهب إلى الإعدادات
# 3. اضغط "اختيار ملف" في قسم الاستعادة
# 4. اختر النسخة الاحتياطية
# 5. اضغط "استعادة"
```

### التراجع بعد الترحيل

> **⚠️ تحذير:** التراجع بعد الترحيل معقد وغير عملي بشكل عام.

**المشكلة:**
- الترحيل يُنشئ Firebase Auth UIDs جديدة
- لا يمكن تغيير Firebase Auth UIDs
- لا يمكن الرجوع إلى UUIDs القديمة

**الحل الوحيد:**
1. أعد تشغيل Migration مع بيانات مختلفة
2. أو أنشئ مستخدمين يدوياً

**الحل الأفضل:**
- لا تُجري تغييرات أخرى بعد الترحيل
- خذ نسخة احتياطية كاملة قبل الترحيل
- اختبار الترحيل على بيئة تطوير أولاً

### جدول جدولة الترحيل

|---------|-------------|-----------|

| مراجعة التقرير | 5 دقائق | |
| حذف كلمات المرور القديمة | 5-10 دقائق | يدوياً |
| اختبار تسجيل الدخول | 10 دقائق | لكل مستخدم |
| **الإجمالي** | **30-40 دقيقة** | |

### أثناء الترحيل
- لا تُغلق النظام أثناء الترحيل
- لا تُجرّ تغييرات أخرى على النظام
- راقب الأخطاء بانتظام

### بعد الترحيل
- اختبار كل مستخدم بشكل منفصل
- حذف كلمات المرور القديمة من Firestore

- الاحتفاظ بالنسخة الاحتياطية لمدة 30 يوم

## الأسئلة الشائعة

### س: هل يمكنني تخطي الترحيل؟
**لا.** بدون الترحيل، لن يتمكن المستخدمون من تسجيل الدخول.

### س: هل الترحيل يحذف البيانات؟
**لا.** الترحيل فقط يُنشئ حسابات Firebase Auth ويُحدّث IDs. البيانات تبقى كما هي.

### س: ماذا يحدث لكلمة المرور القديمة؟
**تبقى في Firestore حتى تُحذف يدوياً.** الترحيل لا يحذف كلمة المرور القديمة تلقائياً. يجب حذفها بعد الترحيل الناجح.

### س: هل يمكنني ترحيل مستخدم واحد فقط؟
**نعم.** يمكنك إنشاء مستخدم جديد من واجهة النظام، وسيتم إنشاء حساب Firebase Auth تلقائياً.

### س: ماذا أفعل إذا نسيت كلمة مرور مدير النظام؟
**أعد تعيين كلمة المرور** من Firebase Console أو أنشئ مستخدم جديد.

### س: هل الترحيل متوافق مع النسخ الاحتياطية القديمة؟
**جزئياً.** النسخ الاحتياطية القديمة قد تحتوي على كلمات مرور. عند الاستعادة، تأكد من حذف كلمات المرور القديمة.
